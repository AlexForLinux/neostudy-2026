Создание набора данных для оценки AI-системы

1. Задача системы и ее фукнции

Задача

Дать пользователю кулинарную поддержку: помощь с рецептами, советами по приготовлению и поиском информации.

Функции

  1. Составить рецепт кулинарного блюда по запросу, содержащего ингредиенты, кухонную утварь и шаги приготовления
  2. Привести справочную информацию в виде совета по кулинарному вопросу (сколько готовить, чем заменить продукт или отсутвующую утварь, как исправить ошибку)
  3. Поддержать естественный диалог при отклонеии от кулинарного курса и вернуться к этому курсу
  4. Производить поиск рецептов и советов по локальных базам знаний
  5. Производить поиск недостающей информации в сети Интернет
  6. Определять достаточность собранных данных для формирования ответа

Рецепты могут варьироваться по сложности. На сложность могу влиять:

  1. Ингредиенты

  • Z2 - Тоже, что и Z1 c добавлением: кастрюля, сковорода, плита, микроволновка, тёрка

4. Стратегия

  1. Поскольку эксплуатация системы на реальных пользователях не производилась и промышленные данные отсутствуют, целесообразно начать с анализа общедоступных источников данных.
  2. Так, на платформе Hugging Face доступен набор данных Hieu-Pham/cooking_squad, содержащий кулинарные вопросы. Однако данный набор не размечен по категориям и сценариям использования, а также представлен на английском языке с уклоном в европейскую кухню. В связи с этим он не может быть использован как основной источник данных, но может применяться как вспомогательный - для повышения разнообразия формулировок.
  3. Поскольку общедоступные источники не покрывают полностью требуемую структуру данных, основным методом формирования датасета выбирается генерация.
  4. Генерация будет производиться на основе ИИ (gpt-oss-120b) с учетом выявленных комбинаций, поскольку отсутсвие реальных данных не позволяет выполнить аугментацию, а симуляция в свою очередь требует построения сложных моделей поведения пользователей и сценариев взаимодействия.
  5. Для каждой из представленных выше комбинации измерений составляется отдельный промпт, описывающий условия генерации, после чего создается N-ое количество примеров. Далее, выполняется фильтрация данных, при необходимости - дополнительная генерация для соответсвия распределению. При формировании промптов могут использоваться примеры из найденного датасета в качестве референсов.
  6. Все полученные примеры объединяются в единую таблицу формата: id - комбинация измерений - пользовательский запрос. Для данной таблицы производится сравнение полученного распределения с желаемым.
